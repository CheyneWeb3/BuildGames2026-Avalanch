# The Haus Cashier — 3–4 Minute MVP Video Script

Target runtime: **~3 minutes 30 seconds**

---

## Slide 1 — Title / Introduction
**Target time:** 0:00–0:20

**Voiceover:**
Welcome — this is **The Haus Cashier**, an Avalanche Fuji MVP built to make web3 applications easier to use, easier to monetize, and easier to extend. The core idea is simple: bring wallet-backed value into a structured cashier system, then let users interact with dapps, games, and social modules through a much smoother experience.

**On-screen actions:**
- Open on title slide
- Briefly mention this is a Stage 2 BuildGames MVP

---

## Slide 2 — Problem and Solution
**Target time:** 0:20–0:45

**Voiceover:**
A big problem in web3 today is friction. Too many apps still ask users to sign a full wallet transaction for every repeated action. That gets painful fast, especially for games, rewards, social spending, and community tools. The Haus Cashier solves that by moving users from direct wallet-only interaction into a structured cashier balance that can support application usage, ledger tracking, rewards, and withdrawals from one reusable foundation.

**On-screen actions:**
- Highlight the “problem” side first
- Then highlight the “The Haus approach” side

---

## Slide 3 — Main MVP Flow
**Target time:** 0:45–1:10

**Voiceover:**
This MVP demonstrates the full user loop. First, the user connects a wallet on Avalanche Fuji. Then they deposit funds into the cashier flow. The dapp shows balances and ledger activity, and those balances can then be used inside the app — in this case through the dice demo. Finally, the user can withdraw funds back out to the wallet. That complete path is important because it proves The Haus is more than a concept — it is a working application flow.

**On-screen actions:**
- Move step by step across the flow boxes
- Transition into the live dapp after this slide

---

## Slide 4 — Dice Demo / Credited Gameplay
**Target time:** 1:10–1:45

**Voiceover:**
Here is the clearest proof point in the MVP: the dice demo. The user plays using cashier-backed balance instead of needing a full wallet transaction every round. I can show spend, win, and lose outcomes, and then point to the way those results are reflected in the balance and ledger. This matters because it makes gameplay smoother for users and much easier for developers to build on top of Avalanche. The same pattern can later support more mini-games, weekly leaderboards, tournaments, and other monetized game loops.

**On-screen actions:**
- Show dice page
- Run a few play tests
- Point to balance and ledger updates

---

## Slide 5 — Telegram as a Modular Integration
**Target time:** 1:45–2:10

**Voiceover:**
The dapp is the main focus of the MVP, but Telegram shows that the cashier is modular. The same underlying balance system can also power a social interface for notifications, account linking, commands, and balance-aware actions. That matters because real communities often live in chats and social tools, not only inside a browser dapp. So Telegram is not the core thesis — it is the secondary proof that one cashier can support multiple user interfaces.

**On-screen actions:**
- Show bot page or chat
- Mention this is optional modular infrastructure, not the main product focus

---

## Slide 6 — Telegram Features: Spending, Lottery, Admin
**Target time:** 2:10–2:45

**Voiceover:**
Inside the Telegram module, I can demonstrate features like wallet linking and registration, balance checks, gift user or tipping flows, notifications when funds are received or spent, and a solvent credited lottery example where users buy tickets directly from credited balance and winnings are returned back into that same balance model. I can also show admin and treasury visibility, which matters because a real cashier system needs operational tooling — not just a frontend, and not just contract calls.

**On-screen actions:**
- Suggested sequence: registration, balance command, gift user, lottery ticket purchase, mainadmin / treasuries

---

## Slide 7 — System Architecture
**Target time:** 2:45–3:10

**Voiceover:**
Behind the MVP is a modular architecture with a core API, tunnel, relayer, indexer, contracts, vaults, and a DB-backed ledger layer. That architecture is what makes the product credible. It means The Haus Cashier is not just one page or one game — it is a reusable foundation that can support dapps, games, social tools, admin modules, and future integrations from the same balance and settlement model.

**On-screen actions:**
- Point to API, relayer, indexer, blockchain, and module boxes in the architecture diagram

---

## Slide 8 — Roadmap / Closing
**Target time:** 3:10–3:35

**Voiceover:**
From here, the roadmap includes future chain expansion using CCIP, richer token flows including swaps, more games and leaderboard systems, and eventually an SDK-style layer so builders can create new cashier-powered modules for payment apps, dapps, mobile gaming, and utility products. The main takeaway is that The Haus Cashier makes Avalanche value easier to use inside real software — and this MVP proves that path today on Fuji.

**On-screen actions:**
- End on the roadmap slide
- Hold the closing line for a second before ending
